# Yxi 界面风格与做法

> 这份是**设计说明 + 实现说明**：为什么长这样、具体怎么做的、以及做错过什么。
> 数字都是代码里的真值，改了界面请顺手改这里。
> 面向对象：接手这个项目的人 / 新会话的 agent。

---

## 0. 立场：这不是聊天软件

Yxi 是**手机上的指挥台**——你不在电脑前，但你的 agent 在跑。所以每一处取舍都往这三条上靠：

1. **一眼扫得到状态**。看板要在一屏里回答「谁在等我、谁在干活、谁停了」，不需要点进去。
2. **单手够得着**。主要动作在拇指扇区（底部导航、输入框、会话卡右下的「回一句」）。
3. **不骗人**。屏幕上动的东西必须对应真实数据——波形来自真实音量，光晕来自真实的忙碌状态，
   「已等你 12 小时」来自状态跃迁的时刻。**没有装饰性的假动效**。

三条派生出来的硬规矩：

- **看得见、点得着**：一个没有可见入口的手势等于不存在（#91：只做了右滑收藏 + 一颗纯展示的星，
  用户第一句话是「我没看见收藏的按钮」）。手势可以有，但必须另有看得见的入口，或者滑动时把字显出来。
- **一切失败都要说出来**：静默失败是这个项目最贵的错（#152 麦克风点了没反应；#233 服务器装了语音识别但 App 判定没装）。
  拿不到就说拿不到，别装作正常。
- **危险动作永远多一步**：终止会话、清空草稿这类都走确认框，不由一个可能是误触的手势独自决定。

## 1. 颜色

### 1.1 主题：两套皮肤，一个抽象层

`LocalPalette` 提供一整套语义色，界面**只读语义名**（`Surface` / `OnSurfaceVariant` / `Muted` / `Dim` / `Copper`…），
不写死颜色。`Skin.Style` 有 `Light`（默认）和 `Dark` 两档，切换即时生效并落盘。

> ⚠️ **终端永远是深底**——彩色输出在浅底上读不了。所以浅色皮肤下切到终端会亮暗跳一下，这是有意的。

### 1.2 状态色（看板 / 对话）

| 含义 | 颜色 | 用在哪 |
|---|---|---|
| 等你 | Amber 琥珀 | 会话卡状态点、「已等你 N」药丸、待批光晕 |
| 干活中 | Teal 青 | 状态点、`✽ Mustering…` 那行 |
| 刚跑完 | Copper 铜 | 「刚跑完 · 13s」 |
| 闲置 | outlineVariant 灰 | 状态点 |

### 1.3 每台主机一个颜色

`hostColor(hostId)` 从 id 哈希派生色相，饱和度 0.5、明度 0.72（深浅两个主题下都不刺眼）。
**同一台机器在看板、配置页、主机列表里永远同一个颜色**——多机时「这是哪台」不用读字。

### 1.4 会员档位色（跟后台一致，不另起一套）

- **Pro**：`#346BF0 → #8AB4F8`（蓝）
- **Ultra**：`#FDBE5A → #F59E8C → #FFE1A8`（琥珀）

### 1.5 品牌与图标底色

Logo 是两片渐变花瓣（透明底）。启动器图标底色 **`#F4F6FA`**——
纯白会吃掉左边那片浅蓝花瓣的边缘，原来的 `#E9E9E9` 灰又把整枚图标压得发闷。

## 2. 对话页的「流动」是怎么做的

这是整个 App 最花心思的一块，三层叠出来的：

### 2.1 整页光晕 `ThinkingGlow`

画在**整个工作区**的最底层（`Workspace` 那个 Box 的第一个子节点），铺满整页。

> ⚠️ 曾经只画在列表那个 Box 里，到列表底边就截止——而快捷语和输入框在外面，
> 于是待机时最亮的地方正好压在那条边上，用户划了条红线指着那道色差。**光晕必须铺到底**。

三态：`busy`（在跑）/ `waiting`（等你批）/ `streaming`（正在吐字），颜色和强度各不同。

### 2.2 色相流动 `glowBrush`

一条**横向渐变**，色相以 **6 秒**一圈循环。透明度：浅色皮肤 0.38，深色 0.22。
输入框和整页光晕共用它，所以两者是同一股「气」，不是两个独立动画。

### 2.3 输入框玻璃壳 `GlassPill`

从下到上六层：

1. **外圈呼吸光晕**：`drawBehind` 画在形状外面一圈的径向渐变，`0.12 + 0.20 × 呼吸`，**2.6 秒**一呼一吸。
2. **半透明底**：浅色 白 0.80 / 深色 `#1C1C21` 0.74 —— 玻璃的「体」。
3. **色相流动层**：同一个 `glowBrush`。
4. **立体**：顶部高光（浅色 0.42 白）→ 透明 → 底部微暗，让它看起来是个有厚度的物体。
5. **流动光带**：一道斜向亮带 **3.8 秒**扫一遍。
6. **玻璃边**：1.2dp 渐变细边（白 → 当前光晕色）。

> ⚠️ **为什么不用 `shadowElevation`（#225）**：Material 的阴影画在面**下面**，
> 面一透明就整个透出来——那就是用户录到的「一大片黑色阴影里面有白色」，
> 边上还留一条没被盖住的白线。**要阴影就给不透明的面；要透明的面就自己画光。**

### 2.4 减弱动效

所有循环动画都读 `Settings.Global.ANIMATOR_DURATION_SCALE`，为 0 就**全部定住**（保留静态渐变和发光）。
这不是可选项——系统设置里开了减弱动效的人，多半是真的需要。

## 3. 上下栏的手感（照 X 的慢动作做的）

**目标**：往下滑（回看历史）时上下栏退场，往上滑（回到最新）时回来；到底了一律展开。

四条实现要点，每一条都是踩过坑改出来的：

1. **跟着手指连续走**，不是「过阈值啪一下收掉」。`onPreScroll` 累加位移 → `barsFrac 0..1`，
   松手过半吸附到收完、不过半弹回来（260ms）。
2. **下栏比上栏退得快**：`hideFrac = barsFrac × 1.7`（用户对着 X 的慢动作指出来的）。
3. **正文一动不动**。页眉的高度算在**列表的 `contentPadding`** 里，不是容器的 `padding`——
   后者是永久空出来一条，页眉一收那块就露底色（#228）。栏是**盖在**正文上的。
4. **悬浮页眉要不透明底 + 底边一小段渐变**：正文从它底下滚过去，不给底就糊成一团。

> ⚠️ 只认手指：`onPreScroll` 里 `source != UserInput` 直接 return。
> 程序滚动（跳底部、跟随）也会走这条，不挡住就会「一收一展」互相抽。

## 4. 列表、卡片、手势

### 4.1 会话卡

三行：`状态点 · 名字 ……… 多久没动 · 已连` / `它此刻的话` / `已等你 N（药丸）· 路径 · 回一句`。

- **左边一条色条**表示身份：收藏 = secondary、置顶 = tertiary、**两者都有 = 两色渐变**。
  （原来是卡片右上角两颗图标，用户要求去掉，改成色条。）
- **左滑拉出一排按钮**（收藏 / 置顶 / 终止），**右滑快捷收藏**。一次只开一张。
  终止仍然走确认框——杀一个会话 = 里面跑着的 Claude 一起没。

### 4.2 跟随到底部

活跃会话每 300ms 来一批新内容。三条规矩：

1. **看得见最后一条时只补差的那几十像素**，不整块跳——`scrollToItem(last)` 是把最后一条的**顶部**
   顶到屏幕上沿，长回复时画面会甩到别处（#228）。
2. **跟随用 170ms 动画滑过去**，不是瞬移。「运动」眼睛能跟上，「瞬移」就是闪。
3. **攒 110ms 再追**：一批内容常分几次到，队列里的消息还会在末尾一冒一消，每次都追就是一秒抽三下。

### 4.3 入场动画只放一次

条目滑入淡入**一辈子只放一次**（用一个 `animated` key 集合记着），而且只有末尾三条内的新内容才动画。

> ⚠️ 这是「一秒闪两下」的真凶（#227）：原来的判据是「是不是进页面之后才出现的」——
> 而 LazyColumn 里条目滚出屏幕会被销毁、滚回来重新组合，判据又成立，于是**反复重放**。

## 5. 图标与排版

- **图标全是自己画的**（`ui/LineIcons.kt`）：24×24 格子里的描边路径，圆头圆角，统一 2 格粗。
  原来用 `◫ ▤ ❖ ⚙` 这类 Unicode 字符——字重、基线、字形全看系统字体，跟界面别的线条对不上。
- **等宽字体**用在路径、token 数、时间码这些「要对齐、要能一眼比对」的地方。
- **药丸（Pill）**是这个 App 的基本形状语言：状态、标签、按钮、快捷语都用它。
- 中文正文行高比英文松——`AiryType` 在浅色皮肤下生效。

## 6. 动效时长表

| 动作 | 时长 | 说明 |
|---|---|---|
| 上下栏吸附 | 260ms | 松手归位 |
| 上下栏跟手 | 0 | 跟手指走，没有插值 |
| 跟随滚动 | 170ms | 内容来了滑过去 |
| 跟随防抖 | 110ms | 安静下来再追 |
| 条目入场 | ~300ms | 一辈子一次 |
| 输入框呼吸 | 2600ms | 一呼一吸 |
| 输入框光带 | 3800ms | 扫一遍 |
| 色相循环 | 6000ms | 一圈 |
| 头像光环 Pro | 12000ms | 转一圈 |
| 头像光环 Ultra | 6000ms | 转一圈 + 3600ms 薄雾呼吸 |

**减弱动效开启时，以上循环动画全部停止**，保留静态效果。

## 7. 反面清单（这些都真的发生过）

| 症状 | 真因 | 教训 |
|---|---|---|
| 输入框周围一大片黑影 | 透明 Surface + `shadowElevation` | 要阴影就给不透明的面（#225） |
| 一秒闪两下 | 入场动画随重组反复重放 | 入场条件是「从没入过场」，不是「是新内容」（#227） |
| 点 ↓ 之后一直跳 | 跟随时 `scrollToItem` 把长条目顶部顶到上沿 | 看得见末尾就只补差值（#228） |
| 兑换码输入串位 | 每敲一个字重排整串再写回 | 格式化只改显示，不改值（#231） |
| 红麦克风从来不亮 | 状态传了一路，**从没被置 true** | 加了状态就搜一遍它被赋值几次（#232） |
| 界面上写着 `null` | `optString` 读 JSON null 给的是字符串 `"null"` | 可空字段统一走守卫（#230） |
| 悬浮通知钉住不走 | 一律标成 `CATEGORY_CALL` + 全屏意图 | 亮屏按消息、黑屏才按来电 |
| 手势互相抢 | 抽屉边缘手势 vs 系统右滑返回 | 一个动作只给一个功能，另一个给可见按钮 |

## 8. 写界面之前先问自己

1. 这个状态是**真的**吗？（数据从哪来，拿不到时显示什么）
2. 失败了用户看得到吗？（不许静默）
3. 这个手势有可见入口吗？
4. 减弱动效时它还成立吗？
5. 深色皮肤下呢？终端里呢？
6. 这一下会不会让正文重排？（重排 = 跳 = 闪）
