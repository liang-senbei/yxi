# 协作消息下一步实现边界

当前代码核对：HubEventCards 的按钮只筛选消息关联；CollaborationHistoryDialog 只读日志。MemberAssignmentDialog 以用户身份创建待发送指令，不是 yxi-hub 的消息回复。

服务器 yxi-hub 的 reply 要求调用者来自 tmux，并核对原消息收件人以及发件、收件双方的实例标识。桌面端不能直接把 SSH 用户冒充某个 Agent 来调用它，也不能仅凭同名会话把旧消息交给新实例。

后续实现应包含两个明确动作：

1. 用户回复：以独立的用户发送者标识进入 hub 事件记录，保存原消息 ID，核对所选协作组与目标实例，使用稳定的新消息 ID 防重复。界面提交前展示接收成员和原消息。
2. 请求 Agent 回复：在原收件任务中创建用户指令，要求其通过现有 reply 协议回复原发件任务；界面先显示本地待发送，后续以实际 hub 事件关联展示，不能把队列加入当作回复完成。

自动协作还需基于真实完成事件调度下一轮，设置轮数/时间预算并在达到限制时停止继续分派。现有暂停组消息仅停止后续投递，不能替代运行器中断。完整实现与验收仍按主 PRD W05，本文不缩减范围。

本批只完成入口与服务器协议核对，尚未新增上述消息动作，也未向现有 Agent 发送业务消息。
