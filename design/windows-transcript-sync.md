# Windows 对话同步修复

## 本轮改动（尚未发布）

- 历史回填与新增内容每 300ms 合批显示，不再等待整段历史传输完成才更新界面。
- 转录起点使用固定文件大小快照计算，避免文件持续追加时起点错位。
- 空行、CRLF 按实际 UTF-8 字节累计；不完整的末行留待后续完整写入后再解析。
- 跟随流每 15 秒重新核对转录路径、大小，断线后保留内容并续接；取消订阅时关闭 SSH 流。
- 修复定向检查发现的流包装问题：不再向转录输出插入心跳空行，防止伪造字节干扰续读位置和半行 JSON；包装器等待子进程并随其退出，确保 15 秒窗口结束后真正重新核对文件。
- 用实际列表底部占位项定位最新内容，长回复不再依赖极大的虚拟索引滚动；用户上翻时暂停跟随，可点击“回到最新”。
- 解析器对历史消息和排队消息的整个快照统一去重，同标识消息以最新文本替换旧值并保留位置，避免重复列表 key 和补全文本滞留。

## 验证分工

hk13 的 cc-yxi 负责必要编译，cc-logto_yxi 负责临时文件的字节边界检查，cc-yxi_pilot 负责解析器同标识消息更新检查。构建错峰、限制 workers 和堆内存；不读取生产对话做测试，也不发送业务消息。

已回收结果：cc-yxi 在 a1bfd31 上完成 compileKotlin 与 compileTestKotlin，成功；cc-yxi_pilot 的独立提交 ccddefe 已合入，5 个解析更新用例和 DesktopTranscriptMemoryTest 通过。前者不覆盖后合入的解析器改动，后者不证明真实 Windows 端到端体验。字节边界与取消链路的结果另行补录。

后续结果：cc-yxi 在 146ce9c 上完成编译及五个定向测试类，26/26 通过（队列 18、转录解析 5、转录缓存 3）。cc-logto_yxi 针对同一提交的流包装器检查 5/5 通过：超时后 EOF、输出逐字节等于文件内容、半行不被心跳截断、模拟 HUP 后退出并清理子进程。此结果覆盖壳层行为，不替代真实 SSH 通道取消和 Windows 界面验收。

## 交付后手动观察

1. 在一条普通会话中生成多段较长回复，确认对话页持续出现新增内容、最终尾段可见。
2. 回复期间向上翻，确认不会被拉回；点击“回到最新”恢复跟随。
3. 切到其他会话再返回、短暂断网再恢复，确认内容接续且无重复。
4. 原生终端重开或切换会话后，对话页应切换到对应转录。

界限：该页面读取 Claude 的结构化转录，终端已经显示但尚未写入转录的文字仍受上游写入时机影响；首次载入保留最近 400 行转录，不代表全量历史。实际应用体验与 Windows 打包发布尚待完成，不能将源码修改视为已更新用户安装版本。
