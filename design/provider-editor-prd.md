# PRD：配置页与紧凑模型映射重设计

版本：0.2 · 2026-09-23 · 紧凑映射已在开发分支实现，整体 PRD 尚未验收或发布。

关联：[本地工作台](local-workspace-prd.md) · [调研与源码依据](research/local-runtimes-2026-09-23.md)。

## 1. 目标与现状问题

直接以用户图5的 CC Switch 为布局参考：高级选项卡片内有清楚的分区标题、同一行输入和模型下拉、整齐对齐的角色/名称/实际请求模型/1M 四列。

Yxi 图4的问题不是缺字段，而是：

- 模型列多了一行“从列表选择”，导致该列与显示名称不在同一水平线上。
- 控件太高、角色列按比例被拉宽、纵向留白过多，五个角色占据了大部分屏幕。
- 模型列表URL、说明和成功消息长期占用大片区域。
- `[1M]` 同时显示在原始模型文本和复选框中，显得重复且混淆真实请求名称。
- 角色只有裸文本，缺少参考图里固定高度的灰底标签，整体看起来松散。

验收标准是可量化的布局与交互，而非“类似 CC Switch”。沿用当前 Yxi 主题颜色；不复刻 CC Switch 的账户或凭据存储逻辑。

## 2. 配置首页

左上显示“本地”或当前服务器名，允许下拉切换；右侧运行器选择使用已验证的官方图标与文字：Claude Code、Codex、OpenCode、Gemini、Grok Build、Hermes。没有运行适配时明确标记能力未接入，不通过图标暗示可用。

每个运行器的第一张固定卡为原生官方账号/订阅（该运行器支持时）；与第三方供应商卡在同一列表。Codex 展示“官方订阅 · ChatGPT”及可核对的登录/方案信息；这不是需要用户手动添加的 API Key 供应商。

第三方卡展示名称、端点主机、连接状态、模型数和可用的额度窗口。额度跟账号/供应商，不能放成整台主机的总额度；未知不显示0或猜测百分比。

选择官方订阅时不显示 Base URL/API Key 编辑框。选择第三方时进入供应商编辑。保存供应商配置和应用到当前 Agent 是两步明确动作；编辑本地供应商不默认改共享原生配置文件。

## 4. 桌面布局尺寸

以100%缩放下的逻辑尺寸为基准；Compose用dp/sp，不能把系统150%缩放误算成行距错误。参考源码的 CSS 36px 对齐目标落为36dp控件。

| 项目 | 规格 |
| --- | --- |
| 页面水平内边距 | 24dp，窄窗口16dp |
| 高级选项卡片 | 1dp浅边框、12dp圆角、16dp内边距 |
| 分区间距 | 16dp；标题与说明6dp；说明与表头12dp |
| 模型表格列 | 120dp / 等分剩余 / 等分剩余 / 104dp |
| 列间距 | 8dp |
| 行控件高度 | 36dp；字体14sp；文字和箭头垂直居中 |
| 行间距 | 8dp；五行总高度目标212dp左右 |
| 表头 | 12sp、中等字重、次要文本色；所有列与控件起点对齐 |
| 角色单元格 | 36dp高、灰色底、1dp浅边框、6dp圆角、左右12dp内边距 |
| 输入框 | 36dp高、1dp边框、6dp圆角；焦点使用主题色，宽度不跳动 |
| 模型下拉按钮 | 输入框内右侧32dp宽；独立可聚焦按钮，不能另占一行 |
| 1M单元格 | checkbox与“1M”同一行；没有能力时保持列宽，显示短横或明确禁用 |
| 顶部工具按钮 | 28–32dp高、图标14–16dp、字号12–13sp，横向对齐 |
| 模型弹层 | 最小280dp、最大420dp宽，最大320dp高；优先贴输入右缘，越界自动翻转 |

实现时使用专用紧凑输入组件或能明确控制 contentPadding 的稳定 Material API。禁止对默认56dp `OutlinedTextField` 只压 `height(36.dp)` 导致裁字。底部错误行有专用空间，但不改变正常状态的行高。

逻辑可用宽度不足约720dp时，四列转为逐角色卡片；卡片内部名称/请求模型有可见标签，触控/窄屏控件至少44dp。不允许硬塞四列导致横向截断。

## 5. 下拉选择交互

点击模型输入框内箭头，弹层上方是搜索框，下方是模型列表；按供应商提供的分组显示，没有可靠分组时平铺，不猜分类。

- ↑/↓移动，Enter选中，Esc关闭并回到原字段；Tab遵循表格顺序。
- 当前项显示勾选；hover浅底，active与selected不可混成厚重浮雕按钮。
- 输入框仍可手填；选择后只更新该角色实际模型。
- 自定义过的显示名称保留；为空或与旧模型自动同步的名称可跟随新模型。
- 长ID单行省略，悬停/详情能看完整值，保存不截断。
- 拉取中显示局部spinner；成功显示短暂“获取到N个模型”，不在每一行下方永久显示操作提示。
- API失败保留已编辑值和上次模型列表，显示可重试原因；不得把失败显示成空模型列表。
- 模型列表URL放“更多请求选项”，默认隐藏；用户输入必须随供应商配置持久化，不能刷新页面就丢失。

## 6. 一键设置与数据语义

一键设置先选择一个真实模型，再将它应用到当前运行器支持的角色；可选择是否覆盖用户自定义显示名称，Subagent不产生菜单显示名。操作可撤销到本次表单先前状态，取消页面不写配置。

内部把 `requestModelId`、`displayName`、`contextDeclaration` 分开存储和校验。表格显示纯模型ID；1M是独立声明，仅在写给对应运行器时序列化必要标记。旧配置兼容解码 `[1m]` 后重新显示，避免双重追加或勾选与文本不一致。

模型列表返回某ID不等于证明它支持1M、图片、工具或高推理强度。分别记录能力来源：原生接口/供应商声明/用户设置/未知；未知不得自动开1M。禁用项给简短原因，不删除用户旧值。

Claude 内部角色名用于配置映射；会话模型菜单显示配置的实际模型/用户别名，第三方线路不再把裸 `opus/sonnet/haiku` 当独立未映射模型。必须保留内部角色与具体请求模型的可追踪关系，不能靠显示文本反推请求值。

OpenCode 使用其 provider/model 标识；Hermes 使用其原生模型选项；Codex 使用当前供应商的真实模型和能力。不要为这些运行器套一张虚假的 Claude 角色表。

协议转换是单独能力：若没有实际代理实现，就不能在下拉里把 Chat Completions 选项表现成可转换为 Anthropic Messages。此页只提供已被后端执行器支持并测试的选项。

## 8. 实施清单及明确不做的替代

1. 从 `RoutesPane` 拆出紧凑映射组件、模型组合输入框、状态消息与高级字段；不在原巨大表单上继续叠加下方按钮。
2. 建立可复用表单密度tokens，作用范围是配置表格，不压缩聊天输入、可访问性或整款应用字体。
3. 数据迁移先保留旧配置及备份，按运行器序列化模型声明；验证实际发送模型，而非只看菜单字样。
4. 按V01–V10提供证据后再作为正式版本发布；CC Switch参考代码如有实质移植保留现有MIT notices并注明来源提交。

建议把“本地顶级入口和Codex原生历史”与“配置页密度重设计”作为两个可独立验收的增量。二者共享执行位置/认证状态模型，避免先画完卡片后再临时接错配置目标。

## 9. 实施复核与剩余验收

紧凑四列表格、窄屏卡片、搜索浮层、键盘选择、1M独立展示、自定义列表URL持久化已实现。复核补正空模型残留 `[1m]`、重复后缀处理及过期一键设置撤销覆盖后续编辑的问题；长模型ID增加完整值悬停提示。具体提交与测试证据见 [实施记录](windows-workbench-progress.md)。

目前一键设置始终保留用户自定义名称，尚未提供“覆盖自定义名称”的选择。1M与纯ID在界面分开处理，线路存储仍兼容既有字符串格式，尚未完成第6节的独立能力/声明数据模型。不得据此宣称已识别供应商真实上下文能力。

通过的隔离测试包括真实Compose键鼠操作、紧凑控件几何、搜索选择、取消、深色/窄屏渲染，以及经SSH保存和读取自定义模型列表URL。现有编辑逻辑测试不替代整页“点击保存、关闭、再打开”的Windows GUI验收；列表接口使用隔离服务，不是用户真实第三方供应商的在线测试。

发布前仍需完成Windows 125%/150%/200%缩放和中文输入法、接口错误页面、整页保存重开及切换主机、官方订阅/第三方身份隔离验收。配置首页的官方账号卡、本地顶级入口、其它运行器映射与能力模型属于剩余PRD，不计入本次紧凑表格交付。1.4.14冻结的是托盘补丁，不包含此表格改版。
