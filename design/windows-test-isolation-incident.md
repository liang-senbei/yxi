# 集成测试隔离事故：2026-09-21

## 已确认事实

- hk13 默认 tmux 在约 22:12 UTC 退出，11 个原有会话中断。
- 未合入主线的 `ConversationRewindFullChainRigTest` 在清理阶段通过 SSH 执行了未限定 socket 的 `tmux kill-server`。
- 测试声称依赖 PATH 包装器隔离 tmux，但没有可靠建立并核对该隔离。测试约 22:12:13 结束，两个用例均失败。仅有回环 SSH、临时 HOME 和测试密钥并不隔离宿主的 tmux。
- 近期内核日志检查未发现相应 OOM 记录。这不是一次通过的端到端测试。

## 已采取措施

- 原测试源码和 XML 保存在服务器受限事件目录；测试已标记 Disabled，未限定 socket 的清理已移除，14 个旧编译类已隔离。
- 检查时未发现仍运行的相关测试 worker 或临时 sshd；不重跑该测试。
- 从事件记录恢复 11 个会话的目录与转录对应关系，并备份 177,945,231 字节的已落盘转录，附 SHA-256 清单。
- 11 个会话窗口已以空 shell 重建，未自动启动 Agent。是否启动开发/业务 Agent，等待用户选择。
- 转录备份证明已落盘内容仍可用，不保证中断时尚未保存的输出或输入可恢复。

## 后续测试必须满足的条件

1. SSH/tmux 集成测试使用独立容器或等效的进程、文件系统及网络隔离；不复用宿主生产 HOME、`/tmp` 或 tmux socket。
2. socket 使用本次测试生成的绝对专用路径，执行前读回核对；清理命令同样必须显式指定它。
3. 初始化失败后，只回收已经证明由本次测试创建的资源；不得通过普通产品连接执行全局清理。
4. 保持主机键校验和权限校验，不能以关闭校验获得测试通过。
5. 假运行器测试与真实 CLI + 假接口测试分别报告，不将前者称为后者的通过证据。

在隔离方案通过复核前，不解除本次测试的禁用状态。事故恢复不等于 PRD 或历史回退功能完成。
