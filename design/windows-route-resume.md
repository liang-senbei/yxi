# 同一 Codex 对话应用线路

状态：开发分支已接入，尚未发布；线上 1.4.1 不包含此入口。

## 使用步骤

1. 在线路设置中选择目标服务器，保存并应用所需线路。
2. 回到已有历史的 Codex 对话，等待当前轮次和审批结束。
3. 点击“在此对话应用当前服务器线路”。程序先读取有效配置，再重新连接原任务。
4. 查看“本次连接配置”，确认提供方和模型；队列的自动发送会暂停，需要时自行重新打开。

原任务编号、历史、输入草稿、附件和队列保留。这个动作不会修改服务器线路文件；它使用前一步已保存、经项目目录解析后的有效配置。

没有发送过内容的新任务可能没有服务器历史文件，此时请新建任务。正在执行、待审批或投递状态不明确时，需要先处理当前任务。

读取配置失败会保留原连接；原连接已关闭而恢复失败时，界面引导点击“连接任务”重新读取历史。重新连接后应确认显示的配置，不能把失败提示当成切换成功。

## 已有证据与待检查内容

hk13 的隔离 Codex CLI 0.153.4 使用本地模拟 Responses 服务完成一轮，随后同编号恢复并保留历史。恢复响应顶层返回新提供方，后续请求访问新提供方端口；历史线程元数据仍保留旧提供方。因此界面分别展示当前连接配置与任务记录模型。

产品接线的定向检查由 hk13 Agent 负责；Windows 实际显示和使用体验留给用户验收。此记录不证明所有运行器版本、模型或第三方协议均兼容，也不涉及真实模型调用。
