## 1. 产品结论

Windows 已有可发布的桌面客户端和主要远程工作链路，但**尚未完整覆盖 Android 功能，也尚未具备本次提出的完整桌面工作台体验**。

下一阶段把 Yxi 做成「跨主机的 Agent 工作台」：选主机 → 选项目路径 → 开任务 → 与 Agent 对话 → 右侧看网页、文件和改动 → 必要时组织多个 Agent 协作。

布局参考用户提供的两张 Codex 截图：左侧导航与项目树、居中对话、底部输入区、左下角账号，以及右侧 Markdown 渲染、文件标签、路径、查看源码与外部打开。网页实时预览还结合官方浏览器文档核对，见 W06。截图和公开交互说明不代表内部架构证据。

v0.2 新增：网页修改实时反馈与样式试调、文件/Markdown 侧栏查看与编辑、服务器本地持久化验收、模型和第三方线路切换。以下均已并入需求、阶段和测试，不是独立备忘。

本轮产物是 PRD；不修改运行中的 Agent、不发布新包、不授予真实账号权益。文中「建议」均为拟议需求，不代表现有产品已经支持。

## 4. 目标用户与核心流程

主要用户：拥有多台 Linux 服务器、多个项目和并行 Agent 的开发者或项目负责人。Windows 是工作台，远程服务器承载代码、工具和 Agent 进程。

核心成功场景：用户在 hk13 的 Yunxi 项目新建任务，确认运行器和插件，发起工作；切到另一台服务器不影响前一任务；收到待批准通知后回到准确任务；在右侧打开该服务器上的开发网页，选中问题元素，把上下文送回同一任务。

首期以已有 SSH 远程主机为基础。「本机」可保留后续扩展位，不能把 Windows 本地执行器假装成已经实现的 SSH 主机。

### 5.2 需要下功夫的 UI

| 位置 | 设计要求 | 验收标准 |
|---|---|---|
| 左上主机选择器 | 主机别名、地区标签、连接状态；可搜索、添加和管理 | 名称相同时仍可辨识；新建任务前始终可见目标主机 |
| 项目树 | 主机下按路径组织项目；项目下为任务；长标题省略、悬停看全 | 同名目录不会合并；任务状态无需进入对话即可识别 |
| 对话头 | 展示主机、项目路径、任务状态；次要操作收进菜单 | 窄窗口仍保留主机身份，不能只剩一个模糊标题 |
| 输入区 | 主动作清晰；附件、模型、权限为紧凑控件 | IME 输入中 Enter 不误发送；上传中不能发半成品 |
| 右栏 | 可拖宽、收起，网页与文件支持标签；每项显示来源主机 | 对话与预览同时可用；切任务不串页面或选择上下文 |
| 账号行 | 头像、名字、权益及到期、版本；点击展开菜单 | 登录失败不显示已登录；会员与模型订阅不混淆 |
| 状态反馈 | 空、加载、断线、失败、无权限、等用户各有明确动作 | 失败后留在原上下文，可重试；不只显示空白 |

建议初始尺寸：左栏 240–300 dp，对话文本最大宽度 760–880 dp，右栏 360–560 dp；在 1280×720、1920×1080 及 Windows 125%/150%/200% 缩放验证。空间不足时右栏改为覆盖面板或单页，避免三栏硬挤。

沿用 Yxi 现有浅/深色与品牌色，学习截图的信息层级、留白和操作位置。动态背景降低对正文的干扰，增加「减少动态效果」选项。状态不能只依赖颜色；核心控件有键盘焦点、可读标签与提示。

不为模仿截图而立即添加空的 Pull Request、定时任务、探索入口；先做可用的任务、插件和协作链路。

## 6. 详细需求

### W01 主机与项目上下文（P0）

- 主机选择器包含「当前主机」「所有主机」视图，以及新增/编辑/测试连接。
- 地区、环境、别名为用户标签；连接状态来自真实连接，地区不自动推断。
- 所有主机视图聚合任务；新建任务、安装插件仍必须指定唯一主机。
- 项目标识为 `hostId + 规范化路径`；任务另有稳定 taskId 与远端 sessionId，不能只靠 tmux 名或目录末段。
- 切主机仅改变浏览上下文，后台运行继续。草稿、附件、终端、预览、审批绑定原任务。
- 首次 SSH 指纹确认、指纹变化、密钥失效均给出可恢复流程。

验收：A/B 两台主机都有 `/work/yunxi` 和同名会话，往返切换后消息、上传、插件配置和通知均无串台。

#### W01-A 本地保存与启动恢复（P0）

现状证据：`Model.kt` 的 Store 已把服务器写入 `%LOCALAPPDATA%\Yxi\hosts.json`，启动侧栏读取；known_hosts 保存指纹，另有旧漫游目录迁移。因此设计上不需要每次重新绑定。**本轮在当前 Windows 用户的 LocalAppData、Roaming 和 `.config/yxi` 候选目录未找到 hosts.json**；这不证明代码未实现，也不证明用户曾成功保存后丢失，需实机复现判定。

- 保存服务器后立即落盘，成功才关闭编辑；读/写失败显示具体可恢复错误，不把读错文件显示成「没有主机」。
- 保留稳定 hostId、别名、地区标签、端口、用户名、私钥引用及连接偏好；密码和密钥秘密使用系统凭据保护。
- 保存采用临时文件＋原子替换，保留最近一份可恢复备份。旧路径迁移只有在新文件复制、解析及校验成功后才清理旧文件；现有迁移对复制失败仍可能继续删源，需修正。
- 重启立即展示已保存主机；默认恢复上次选择，可设置自动重连。**记住服务器与保持 SSH 连接是两件事**，离线不能要求重新添加服务器。
- 自动重连不得绕过指纹变化检查，不自动新建 Agent；恢复到已有任务。软件升级、退出账号不清空独立保存的主机配置。
- 导出默认不含秘密，导入做冲突预览与去重；不默认同步服务器密码到云。

验收：添加两台 → 完全退出 → 再启动 → 两台仍在；再测升级、掉网、令牌退出、只读目录、损坏 JSON、迁移复制失败。失败时原配置仍可恢复，无静默清空。本轮不关闭正在运行的客户端做此测试。

### W02 新对话与运行器（P0）

流程：新对话 → 主机 → 最近项目/选择目录 → 运行器 → 显示生效插件与权限 → 输入任务并启动。

- 保留复用已有会话；新建前检测路径权限、tmux、运行器可执行文件及认证状态。
- 路径支持空格、中文；显示真实目标，创建不存在目录时明确告知。
- 运行器通过适配层提供，首期接已验证的 Claude 路径；Codex 或用户所说 Laize 经探测与适配后开放。
- **Laize 名称/命令尚未确认。**目前源码实际是 `Dirs.createCommand(dir, name, "claude")`，不能写成已支持 Laize。
- 启动后验证目标 cwd、进程与会话身份，再标为运行中；重试不能重复创建。
- CLI 未登录时进入该运行器的认证流程；Yxi 账号登录不能替代服务器 CLI 登录。

验收：未装运行器、无目录权限、路径重名、SSH 中途断开、双击启动都有确定结果；失败不留看似成功的任务卡。

### W03 插件与服务器匹配（P1，数据模型 P0）

沿用 ConfigRemote 的主机配置读取能力，补成可操作的插件管理。

- 插件详情显示来源、版本、支持的 OS/架构、运行器、依赖、权限和安装位置。
- 安装时选择主机与作用范围：用户级或项目级；每台主机单独显示已安装、需登录、不兼容、失败等状态。
- 插件定义可以共享；配置与凭据按账号/主机/项目隔离，不因「安装到另一台」自动复制秘密。
- 操作包括安装、配置、测试连接、启停、升级、卸载；失败可重试，变更前保留可恢复版本。
- 安装结束须验证运行器实际识别插件。配置文件写成功不等于插件可用。
- 运行中的任务显示「下个会话生效」或经过验证的热加载状态，不伪报即时生效。
- 项目配置覆盖用户默认时展示最终值及来源；变更前显示目标主机与路径。

验收：插件只装到 A，B 不应显示已安装；A 凭据不会进入 B；断线安装结果可查询；卸载不破坏无关配置。

### W04 登录与三个月权益（登录 P0，权益规则待确认）

当前实现：系统浏览器 OIDC + PKCE，固定 `127.0.0.1:1455/callback`，本地保存令牌，调用 `/api/me` 展示资料与权益。

需要补齐：

1. 登录状态机：未登录 → 等浏览器 → 验证回调 → 换令牌 → 获取账号 → 成功。换令牌前浏览器只能显示「授权已收到」，不能提前宣告登录成功。
2. 端口占用、取消、超时、多次点击、过期授权、错误 state、网络故障都有可重试提示；不把重启电脑作为唯一解决方式。
3. 回调监听地址与注册 redirect URI 一致；校验请求路径与参数，处理无关请求，反馈页面内容安全转义。
4. access/refresh token 用 Windows 用户级凭据保护（例如 DPAPI），写入失败不能悄悄当成功；现有 `auth.json` 迁移后验证并清理旧明文。
5. 重启、续期、退出、账号切换、服务端撤销完成闭环。临时断网不误退出登录。
6. 单独呈现三种身份：Yxi 账号、服务器 SSH 身份、Agent 提供方登录状态。

**三个月规则暂定解释：**测试用户完成登录与规定的试用任务后，可获得 Yxi 三个月权益。这是评审假设，不是已确认业务规则，也不是自动修改真实账号的授权。

- 待确定「三个自然月」还是「90 天」、会员档位、覆盖额度、领取资格、是否所有用户可领、已有会员如何叠加。
- 服务端判断资格和到期时间，以用户 ID + 活动 ID 做幂等；客户端重复点击、重装、换主机均不能重复发放。
- 记录授予原因、起止时间和操作流水；账号页显示何时生效、何时结束、具体包含什么。
- 测试通过使用指定测试账号和服务端记录；浏览器进入登录页、Agent 自述测试通过，都不能触发发放。
- 登录测试先使用测试账号/测试权益；没有测试凭据时报告阻塞，不用生产账号模拟领取。

验收：正常登录、拒绝授权、端口占用、无效回调、续期、重装、重复领取、已付费账号、到期降级均有证据；本轮未执行完整交互登录或真实授予。

### W05 官方 Agent 协作模式（P1）

「官方分支」可能指 Git 分支，也可能指正式支持的协作产品模式。暂按后者设计，与会员有效期和软件发布版本分开；准确命名待确认。

- 接续现有 Groups/组规及 yxi-hub 通信机制，先盘点真实协议和可查询状态，再做界面。
- 组内展示成员主机、项目路径、任务、状态和负责人；提供指派、定向发消息、回复、汇总、停止协作。
- 消息记录发送者、接收者、任务关联、时间、送达/处理状态；重试要去重。
- 分开「看协作记录」与「让 Agent 自动对话」；自动协作有轮数/用量预算、超时、循环检测和停止按钮。
- 涉及同一仓库的写入采用明确文件归属或独立 worktree；合并前检查冲突，不让多个 Agent 无序改同一文件。
- 跨服务器协作另设授权边界；先完成 hk13 的 Yunxi 组闭环，再推广跨主机。
- 审批属于具体任务，不能把一个成员的批准传播成整个组的无限权限。

验收：A 指派 B → B 回复 → A 汇总可追踪；重复投递只执行一次；成员离线有状态；到预算能停；停止协作不删除已有任务和记录。

### W06 右侧网页预览与选择（P1）

**Codex 可借鉴的实际交互：**官方文档描述启动开发服务器、在应用内打开页面、结合代码差异查看结果、选元素或框选区域留下评论，再让 Agent 修改并复查。文档还描述 Adjust：临时调整字体、文字、间距、颜色并预览，再连同评论提交目标。这支持「边看边指导修改」的产品方向；并不能证明它使用哪种文件监听/HMR内部实现。[OpenAI 官方 Browser 文档](https://learn.chatgpt.com/docs/browser?surface=app)

#### W06-A 修改即时可见（P1，核心验收）

- 核心闭环：打开项目预览 → 用户指点页面 → Agent 修改真实源文件 → 开发服务器编译 → 右栏刷新结果 → 用户继续指导。无需每轮复制 URL、重新打开浏览器或重新部署。
- 项目可保存预览启动命令、工作目录、远端端口、就绪检测；再次打开复用健康进程。失败展示编译/服务日志入口，明确区分「服务没启动」「编译失败」「隧道断开」。
- 支持 HMR 的项目透传其 WebSocket 更新；不支持时在构建成功后自动刷新，另保留手动刷新与暂停自动刷新的选项。服务仅返回旧页面时，不能标成最新。
- 顶部状态显示「修改中 / 构建中 / 已同步 / 构建失败」，记录最近成功更新时刻与关联改动版本；失败时标明当前显示的是上次成功版本。
- 尽量保留路由、滚动位置和选中目标；完整刷新可能丢失表单状态时明确提示。评论锚点找不到时显示已过期，不自动绑定另一个元素。
- 若用户在右侧源码编辑器手动保存，走同一更新流程；尚未保存的编辑显示脏标记，不能声称已进入 Agent 或服务端构建。
- 用户点击元素/框选区域，输入「这里再窄一点」即可把目标、评论和当时画面绑定到当前任务。Agent完成后提供代码 diff 和当前预览供核对。
- 增加样式试调：调整字号、颜色、间距或文字，立即看到临时效果，可撤销/重置；点「交给 Agent 应用」后形成修改需求。**临时 DOM/CSS 效果与真实源文件已保存分开标识**，不能只改页面就报告代码完成。首期试调限定自有开发页面；选择评论与自动更新不能等该增强才交付。
- 已发布静态 URL 只有部署后才会变化，明确标为发布预览；开发预览不自动触发线上发布。

验收：改一处文字、样式、组件，右栏连续看到更新；HMR失效走刷新降级；编译错误不会假报成功；切任务、重连后回到准确项目。目标：开发服务器报告构建成功到右栏呈现更新，在受控测试网络下 P95 ≤2 秒（不含 Agent生成/构建耗时），分别记录各段耗时。

首期能力：网页标签、前进/后退/刷新、地址、载入/错误状态、在外部浏览器打开；后续叠加元素选择。

- 远端 `localhost:3000` 指的是被选服务器，不是用户 Windows。通过该任务所属 SSH 连接建立本地回环隧道，端口冲突自动分配。
- 页面显示「hk13 → 远端 3000」来源；隧道绑定 hostId/taskId，断开可恢复，关闭预览可回收资源。
- 支持常见开发服务器 WebSocket/HMR；基础 HTTP 成功不等于预览完整可用。
- 文本选择或元素选择形成可查看附件：URL、主机、时间、选中文字、截图区域、定位信息（可获得时）。用户点「加入对话」后才发送。
- MVP 先支持可控开发页面；跨域 iframe、canvas、浏览器限制等无法定位时降级为截图/文字，不伪造 DOM。
- 预览内容是任务输入，不自动取得执行命令、读取任意文件或授权插件的能力。
- 浏览器身份按工作区/主机策略隔离；敏感输入值不进入选择附件。Yxi 自身 OIDC 登录继续使用系统浏览器。
- 非 http(s) 导航、下载、弹窗有明确处理；TLS 失败不能静默忽略。

**技术决策门：**当前是 Compose JVM，无现成网页组件。先验证 Windows 嵌入浏览器方案与 Compose/Swing 混排：键盘焦点、IME、DPI、层级遮挡、WebSocket、生命周期、分发体积与更新维护；通过后再确定内核和桥接库。此稿不指定未经验证的库，也不为加一个右栏直接重写整个技术栈。

验收：两个服务器相同远端端口同时打开不串台；选择回到原任务；切任务/断 SSH/关闭标签行为明确；与真终端同时显示无遮挡和焦点抢占。

### W08 文件与 Markdown 右侧预览/编辑（P1）

目标按用户第二张截图：点击对话中的 PRD、代码或文件链接，即在右侧打开标签；左侧对话保留，可边看文档边提出修改。

- 文件标签显示文件名，顶部显示来源主机与完整路径面包屑；支持关闭、切换、拖宽、展开、复制路径和外部打开。
- Markdown 默认渲染标题、列表、表格、代码块、图片和链接；提供「预览 / 源码 / 分栏」切换。代码提供语法高亮、行号、搜索与定位；文本、图片为首期基础类型。PDF/Office 后续扩展，未支持时明确下载/外部打开。
- 点击对话文件链接无需复制路径。解析当前任务所属主机与项目，严格区分 Windows 本地路径和服务器路径；相对图片/链接按文档目录解析，不串到另一服务器。
- Agent 改动磁盘文件后预览自动更新，并尽量保留阅读位置；可定位到改动位置或切到 diff。远端通过文件版本/哈希检测变更，断线显示缓存和更新时间。
- 源码模式可编辑文本，Ctrl+S 保存到正确文件；用户未保存时其他 Agent 改了同一文件，显示版本冲突，提供比较/合并/另存，禁止静默覆盖。
- Markdown 不执行脚本；外链资源有来源边界。大文件采取限量加载或明确外部打开，不一次读入整个日志。
- 文件选择文字/代码行可「引用到对话」，带来源主机、路径、行号、版本和选段；内容变动后旧行号标为历史位置。
- 「外部打开」对远端文件使用可验证的远程编辑器入口；无可用集成则下载副本并标为本地副本，不暗示会写回服务器。

验收：点击本 PRD 在右栏看到排版；Agent改表格后自动更新；同名文件跨主机不串；源码保存后预览更新；未保存编辑遇远端变更能提示冲突；中文、相对图片、长代码块可读。

### W09 模型与第三方路由线路切换（P1，配置隔离 P0）

现状：桌面 `ChatPane.kt` 的模型 Chip 没有点击切换动作。安卓 `Lines.kt`、`LinesPanel.kt`、`LinePresets.kt` 已有线路/模型配置基础，包含 Claude 与 Codex 分支；桌面不能仅移植 UI 标签就算完成。现有预设的提供商、模型、端点需在实施时验证，不把源码列表当作当前可用承诺。

- 输入区提供「运行器 → 线路 → 模型 → 思考强度」选择，并显示目标主机、作用范围、生效状态。模型菜单随线路能力变化，不提供该线路不支持的假选项。
- 线路支持官方登录、官方 API、自定义第三方兼容端点；新增/编辑包含名称、提供方、协议类型、Base URL、凭据引用、模型 ID/映射、备注。路径拼接规则由适配器处理，避免重复 `/v1` 等错误。
- 线路列表按服务器管理，复用安卓服务端 `~/.yxi/lines.json` 数据时保持兼容并先做版本化迁移。项目覆盖用户默认须展示来源；本地仅保存界面偏好与受保护凭据引用，不建立虚假的第二份当前线路状态。
- 保存前校验格式；「测试线路」从**选定服务器**发起，区分网络、认证、模型不存在和协议不兼容，展示延迟与可验证的模型能力。可能产生计费的小请求在测试动作说明中写清。
- 当前状态从实际配置回读，分别显示「已保存配置」「待会话生效」「已验证请求」；模型别名与返回模型字段可并列，但第三方自报名称不等于底层模型身份保证。
- Claude/Codex/其他运行器分别实现切换契约。已有安卓代码区分可在后续请求生效与需重开字段；Windows 按运行器版本与实测结果显示生效时点，不能承诺全部热切。
- 正在生成时，排队到本轮结束应用或由用户选择停止后切换；不把同一轮请求混到两个提供方。必须重开时保留转录/草稿，说明会话连续性的实际限制。
- 用户级线路可能影响同一服务器上的多个 Agent。应用前列出影响范围；未验证项目/会话隔离时不得提供「只改当前任务」的虚假承诺。
- 切回官方登录清理适配器管理的旧端点/凭据/模型映射，保留无关配置并回读验证；第三方凭据默认遮罩、导出脱敏、日志不记录。
- 切换失败保留或恢复上一份配置并展示实际状态。默认不静默故障转移；后续若做自动备用线路，须由用户启用并明确费用/数据目的地变化。

验收：A/B两台主机各设一条不同线路；切A不改B；模型选择确实进入请求；错误 key/不支持模型/协议失败可识别；切回官方无残留第三方配置；生成中切换不丢任务；外部工具改线路后 UI 能重新读取真实状态。
