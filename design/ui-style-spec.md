# 规格表：Code 风格（M0 实测 v4）

版本：v4 · 2026-09-28 · 配套 [PRD](ui-style-prd.md) v0.6。数值来自用户在本机分五轮拍的参考端截图（可用 50 张）和一段约 8 分钟的录屏（参考端 = PRD §5 的对标客户端，第一轮时版本 2.9939.2）。素材只在本机，量完即删，本文只有数值（PRD §2-4）。

v1 → v2：补量第二、三轮素材（审批卡三种、右侧面板、会话头、设置通用页、侧栏收起、深色一张）；圆角换量法后整体改小 1～2（§0.2、§1.7）。

v2 → v3：补量第四轮（思考内容、排队、分支下拉与 worktree 勾选、会话行 hover 与多行 tooltip、消息之间的纵向节奏）；§0.4 的细线规则推广到任意缩放；更正「最新一条消息的操作行常显」（§3.4）；新增 §7 macOS（还没有素材，只列差异和待测项）。

v3 → v4：补量第五轮（对话视图子菜单；带工具调用的三档对比；工具摘要行、工具组卡片、命令框与输出、文件内容框；有文字的输入卡），见 §3.4、§3.9。更正：子菜单和父菜单的间隔（2.4 → 1.6，§3.1）；发送图标的灰度跟焦点走、不跟有没有文字（§3.2）；输入卡文字起点 ≈12 → ≈10（§3.2）；代码块圆角改用描边拟合（6～7 → 8，§1.7）。

单位：除特别注明，都是 CSS px，等于 Compose 的 dp。「≈」是估算，误差见 §0.3。

### 0.2 量法

- 坐标：窗口左上角为原点，物理像素 ÷ 1.25。
- 平涂色：取区块内部像素的中位数，避开抗锯齿边。文字色：取字形最深的像素，小字号会偏浅约 3 级。
- 圆角：取直边的横截面，得到「离边距离 → 颜色」的过渡曲线；用它渲染不同半径的角，与实图比平方误差，取误差最小的半径（合成图验证无偏）。记填充边缘的半径；带外环的，外环外缘 ≈ +1。v1 用四角缺失面积反推，普遍偏大 1～2，已按新法重测大部分（§1.7 注明没重测的）。
- 阴影：浮层开、关两帧逐像素相除得 alpha，拟合成「描边 + 两层高斯」。
- 动效：录屏逐帧差分，分辨率 33 ms（1 帧）。

### 0.3 误差与置信度

- 截图（无损）：几何 ±0.4，平涂色 ±1 级。
- 录屏（有损）：平涂色整体偏约 1 级（#FCFCFB 录成 #FBFBFB），1 物理像素的细线会被压淡。v1 里标「录屏」的颜色都已换成截图值，录屏现在只用来量动效。
- 时长 ±33 ms，缓动只看得出趋势，精确曲线要 DevTools（PRD §9）。
- 字重只能目测出常规 / 半粗 / 粗三档。参考端用的是品牌字体，字宽和 Segoe UI 不同；字号按大写字母和 x 高度推算，±1。

### 0.4 1 物理像素的细线

- 参考端的分隔线在 125% 下正好是 1 个物理像素，两侧没有过渡像素（不是 1.25）。
- 原因是浏览器内核对 border 宽度有取整规则：宽 w 的 border 画成 max(1, ⌊w × 缩放⌋) 个物理像素。CSS 1px 在 125% 下画成 1 物理像素（0.8 CSS）。所以带 border 的小控件（复选框、行内代码、设置行分隔、树列分隔）也都是 1 物理像素。
- Compose 的 `1.dp` 不取整，在 125% 下是 1.25 物理像素，会糊成两行浅线。分隔线和这类边要写 `(max(1f, floor(density)) / density).dp`，下文记作「细线」。按这条规则：100%、200%（macOS Retina）时就是 `1.dp`；125%、150%、175% 时是 1 物理像素；250% 时是 2 物理像素。只有 125% 实测过，其余按规则推算。
- 卡片、浮层的外框是阴影式描边，不取整，是约 1.25～1.6 物理像素的抗锯齿环，任何缩放都用 `1.dp`，下文记作「外环」。

## 6. 还缺什么

- macOS 素材见 §7.3。

碰到再顺手拍，不专门安排：

- 状态：未读 / 置顶行；其他输入框的焦点环；按下、不可用；toast；多行输入；开关打开；工具行的流光动效；会话行「⋮」点开的菜单。
- 工具调用：同一条摘要行鼠标在上 / 不在上各 1 张（核对 §3.4「静止弱色、hover 次色」的推测）；普通档点开卡片时执行命令条目是不是默认展开；长输出截不截断；进行中的卡片。
- 结构：首次访问网站的审批卡；对话宽度「中 / 宽」、字号「小 / 大」；终端用的字体；多个分支时的分支下拉；改动面板里有多个文件时的文件列表。
- 语义：上下文环什么时候变琥珀；手动、跳过权限以外的权限模式标签色；失焦时占位符换成建议的条件（§3.2）。

100 / 150 / 200% 缩放，以及 1200×800、1280×720、1920×1080 窗口只验布局，不再量数值（PRD §7）。

| 托盘图标 | 任务栏托盘 | 菜单栏图标，单色模板图，跟随浅色 / 深色菜单栏 | — |

### 7.2 实现要点

- 窗口：不能用 `WindowDecoration.Undecorated`（Main.kt 现在用的），Mac 上会丢红绿灯和原生全屏。保留系统边框，在窗口的 root pane 上设 `apple.awt.fullWindowContent`、`apple.awt.transparentTitleBar` = true，`apple.awt.windowTitleVisible` = false，让内容画到标题栏下面；自绘顶部条照旧当拖动区，左上给红绿灯留位。打包用的是 Temurin 21 不是 JetBrains Runtime，没有自定义标题栏的 API，红绿灯位置挪不了，参考端如果挪过，Yxi 在这点上对不齐。
- 菜单栏：用 Compose 的 `MenuBar`；关于、设置、退出接 `java.awt.Desktop` 的 about / preferences / quit handler，退出走 Main.kt 现有的 `quit()`（有未保存的工作会先确认）；点 Dock 图标重新打开窗口接 `AppReopenedListener`。
- 快捷键：Shell.kt 的 `shortcut()` 现在只认 Ctrl，改成「主修饰键」，Mac 上是 ⌘；切会话的 Tab 那条例外，Mac 上仍是 ⌃。Shortcuts.kt 的清单、键帽、tooltip 里的键名跟着换。终端里的 Ctrl 组合键照旧原样发给终端（⌃C 是中断），复制粘贴用 ⌘C / ⌘V。
- 字体：要在真机上核 Compose 的默认字体在 Mac 上落到哪、中文是不是回退到苹方、SF Mono 能不能按名字取到。
- 颜色：大多数 Mac 屏是 Display P3。要核 Compose（Skia）有没有把 sRGB 值转到屏幕色域；没转的话同一个 #FCFCFB 在 Mac 上会比参考端艳。
- 托盘提示：Main.kt 里「Yxi 会在托盘里继续运行」在 Mac 上改成菜单栏的说法。

### 7.3 要拍的 Mac 素材

有装着参考端的 Mac 时再拍。环境：系统默认的 Retina 缩放；窗口按住 Option 点绿灯铺满屏幕（不是全屏），记下窗口的 CSS 尺寸；浅色；界面字体默认；顺手记参考端的版本号。

- 会话页（侧栏展开，有运行中的会话）、新会话页、设置、任意一个浮层（如模型）、侧栏收起。
- 原生全屏 1 张。
- 菜单栏：每个菜单展开各 1 张。
- 鼠标停在红绿灯上 1 张（看顶部条的 hover）。

量法：物理像素 ÷ 2。Mac 截图带 Display P3 描述文件，取色前按内嵌的描述文件转成 sRGB，或者拍之前把显示器的描述文件切到 sRGB。
