# iOS 版和 Android 版的差异

> 日期：2026-08-23 · 作者：ios-push
> **这份是给你看的，写得诚实。做不到的就写做不到，不会为了好看说成「可以」。**
>
> ⚠️ 作者没有 Mac、没有 iPhone、没有开发者账号，**一个字都没有实机验证过**。
> 没有出处链接的推断都标了「（未验证，推断）」。
> 细节见同目录的 `背景通知.md` 和 `分发.md`。

---

## 0. 一句话总结

**iOS 版能做到的事和 Android 版基本一样，但有三件事必须换做法、两件事直接做不到，
换来的是三件 Android 上根本得不到的好处。**

| | 数量 | 是什么 |
|---|---|---|
| ❌ **做不到** | 2 | 从服务器直接装 App、App 自己装更新 |
| ⚠️ **必须换做法** | 6 | 手机主动响、通知上直接批、后台常驻、开机自起、SSH 库、私钥存哪 |
| ✅ **iOS 反而更好** | 4 | 不耗电、不被系统杀、灵动岛、Secure Enclave |
| ✅ **一样** | 其余全部 | 看板 / 对话 / 终端 / 文件 / 语音 / 用量 / 送指令 |

---

## 1. 完整对照表

### ❌ 做不到的（2 条）

| 功能 | Android 怎么做 | iOS 怎么做 | 代价 |
|---|---|---|---|
| **从自己服务器装 App** | 服务器上放 APK，手机点一下就装 | ❌ **没有等价物**。iOS 没有「未知来源安装」。<br>最接近的是 **AltStore 自建源**（自己服务器上放一个 JSON + IPA，AltStore 提示更新） | **要么每 7 天在手机上重刷一次（免费账号），要么 ¥688/年（付费账号，一年刷一次）**。<br>而且**必须借一台 Mac 编译**，这是硬门槛 |
| **App 自更新** | `Update.kt` 走 SFTP 取包 → FileProvider → 拉起系统安装器 | ❌ **App 不能安装 App**，iOS 没有 `REQUEST_INSTALL_PACKAGES` 这种东西。<br>能保留的只有**前半截**：SFTP 读 `~/.yxi/latest.json` 比版本号 → 显示「服务器上有 0.3.0」→ 给一个可点的链接（`altstore://` 或 `itms-services://`） | 更新从「点一下就好」变成「点一下跳到 AltStore，再点一下」。<br>⚠️ 还有个没干净解的矛盾：AltStore 源要 **HTTP(S) 可达**的 IPA 直链，而 `~/.yxi/` 现在只走 SFTP（PRD §2.3 特意不开 HTTP 面）。见 `分发.md` §5 |

### ⚠️ 必须换做法的（6 条）

| 功能 | Android 怎么做 | iOS 怎么做 | 代价 |
|---|---|---|---|
| **手机主动响** ⭐ | 前台服务常驻一条 SSH 通道 `tail -f ~/.yxi/events.jsonl`，收到就发本地通知（`EventService.kt`） | ❌ 常驻连接做不到。<br>✅ 改成 **push**：<br>**零成本**——自建 bark-server → Apple APNs → App Store 的 Bark App<br>**$99**——自己的 `.p8` → APNs → Yxi 自己的通知 | 那一声响**必须过 Apple 的 APNs**（iOS 上唯一的合法唤醒通道，没有替代）。<br>好消息：**不经过我们的服务器**，Bark 还支持端到端加密（Apple 只看得到密文）。<br>服务器侧多一个**可选的独立脚本**（不碰 `yxi-hook`，安卓版零影响） |
| **是谁在响** | Yxi 自己的图标 + 自己的通知渠道（`yxi.events` 高优先级 / `yxi.ongoing` 最低），可以分别调 | **零成本方案**：⚠️ 锁屏上是 **Bark 的图标和名字**，通知分组、声音、免打扰全归 Bark 管，你别的监控告警和 Yxi 的事件**混在同一栏**<br>**$99 方案**：✅ 跟安卓一样，Yxi 自己的图标和渠道 | 免费路线下这是**最明显的体感差异**。点进去能跳回 Yxi，但「谁在响」不一样 |
| **推送通道的可靠性** | 自己的 SSH 连接，只取决于你的服务器 | **零成本方案**：⚠️ bark-server 用的是 **Bark 内嵌的、全世界共用的一把 APNs 私钥**（明文在开源仓库里）。Apple 一旦吊销 / Bark 主动轮换，**所有自建 server 同时哑掉**，要等上游发新版再重新部署<br>**$99 方案**：✅ 自己的 `.p8`，**这个单点消失** | 目前看 Bark 活得很好（MIT、3.6k star、2026-07 还在更新），但**选它就是接受这个风险** |
| **通知上直接批准/拒绝** ⭐ | 通知带按钮 → 广播 → **重新抓屏确认指纹** → `send-keys`（`EventService.answer()`） | **零成本方案**：❌ **做不到**。Bark 是通用推送 App，通知上只能点击跳 URL，没有自定义按钮 → **必须点开 Yxi 才能批**<br>**$99 方案**：✅ 能做（`UNNotificationAction`） | 免费路线下**审批多一步**（点通知 → 开 Yxi → 按）。<br>$99 路线下也有坑：通知按钮的后台执行窗口**只有约 10 秒**，要塞进「SSH 握手 + 抓屏确认 + 送键」。<br>⚠️ 建议按钮默认设成「点了开 App」，后台直批做成可选开关 —— **宁可慢一步，绝不能批错**（安卓版那条纪律一个字都不能省） |
| **后台常驻连接** | 前台服务 + `START_STICKY` + 电池白名单引导 | ❌ **系统不给**。App 切后台约 **30 秒**后被挂起，SSH 连接断 | 所有「后台自己去看」的逻辑都要改成「**push 叫醒 + 打开时补齐**」。<br>好消息：安卓版那套「连上先 `tail -n 300`、按上次看到的时间戳过滤」的补漏逻辑**原样能用**，只是触发时机从「后台一直连着」变成「每次打开 App」 |
| **开机自起** | `BootReceiver` 监听 `BOOT_COMPLETED` | ❌ 没有对应物 | **不需要**。APNs 不依赖 App 活着 —— 手机重启、App 被上滑杀掉、几天没打开，**照响** |
| **SSH 库** | `mwiede/jsch`（纯 Java，gradle 一行依赖，自带 SFTP） | Swift 生态要选：**Citadel**（对 NIOSSH 的高层封装）或 **NIOSSH**（Apple 官方，但只给积木、不给成品客户端） | ⚠️ **这是 iOS 版最大的工程风险，比通知大。**<br>NIOSSH 官方明说「不提供 production-ready 的客户端」；Citadel 的 **SFTP 客户端支持和 PTY 支持成熟度未验证**，社区有专门 fork 出来暴露 PTY API 的分支。<br>→ 直接影响 P0-11 文件浏览（走 SFTP）和 P0-2 真终端。**这条要 ios-core 尽早探路** |
| **SSH 私钥存哪** | Android Keystore + BouncyCastle 撑 ed25519（决策 D20） | ⚠️ **要重新选算法**：Secure Enclave **只支持 NIST P-256**，**存不了 ed25519**，而且**只能在里面生成、不能导入**。<br>两个选择：<br>① `ecdsa-sha2-nistp256` 放 Secure Enclave（**硬件级、私钥永不可导出**）<br>② 继续用 ed25519，放 Keychain（软件保护 + Face ID 门禁） | 选 ① 的话，iOS 版和 Android 版**是两把不同的密钥** —— 无所谓，两个公钥都往 `authorized_keys` 里放就行（P0-14 一键装公钥本来就干这事）。<br>**建议选 ①**：比 Android 版的软件 ed25519 **更安全**（见下面「iOS 反而更好」） |

### ✅ iOS 反而更好的（4 条）

| 功能 | Android 的情况 | iOS 的情况 | 说明 |
|---|---|---|---|
| **耗电** | 常驻一条 SSH 连接，几十秒一次心跳，日常掉几个百分点（PRD §2.7 自己承认的代价） | **接近 0** | 不常驻任何东西，push 是系统在收 |
| **被系统杀** | 荣耀 MagicOS 后台管控狠，要引导用户加电池白名单 + `START_STICKY` + 开机广播，还是可能被杀 | **不存在这个问题** | 本来就不常驻，没什么可杀的。<br>PRD §2.7 列的三条「前台服务的真实代价」（常驻通知划不掉 / 耗电 / 国产 ROM 杀后台）在 iOS 上**全部消失** |
| **通知栏常驻一条划不掉的通知** | ✅ 有（前台服务的系统要求） | **没有** | 干净 |
| **灵动岛 / 审批倒计时** | 只能等 Android 16 Live Updates（API 36，且完整体验先在 Pixel 上放）；厂商私有的「灵动胶囊」要走大厂合作，判定走不通（决策 D9） | ✅ **Live Activities 是 iPhone 原生系统能力**，iOS 17.2 起服务器还能**远程开启**（push-to-start） | **这是 Moshi 有、我们安卓版做不到的那条**（PRD §5.5 第 18 条），在 iOS 上**能做**。<br>前提是 $99（要 Push Notifications capability） |
| **私钥保护** | Android Keystore，但 ed25519 靠 BouncyCastle 软件实现 | Secure Enclave 的 P-256 私钥**物理上无法导出**，连系统自己都读不出来 | 前提是接受换成 P-256（见上面那张表） |

### ✅ 完全一样的

这些跟平台无关，逻辑可以直接照搬，只是换语言写：

- **会话看板**（`cc-*` 枚举 + `~/.cloud-status/*.json` 状态 + 三列分组）
- **对话模式**（读转录 jsonl 渲染，不刮屏）
- **真终端**（`tmux attach`；渲染控件用 [SwiftTerm](https://github.com/migueldeicaza/SwiftTerm) 对应 Android 的 termux terminal-view）
- **文件浏览**（SFTP 只读）—— 但受上面 SSH 库那条风险影响
- **快捷发指令**（`tmux send-keys`）
- **键盘工具条 / D-Pad 方向键盘**
- **语音输入**（`SFSpeechRecognizer` 对应 Android `SpeechRecognizer`；「命令行模式下必须先确认再发送」这条纪律照旧）
- **用量显示**（`ccusage` + 转录里的 usage 字段，纯服务器侧数据）
- **一键装公钥**、`known_hosts` 指纹确认、多主机
- **服务器侧**：`yxi-hook` / `events.jsonl` / `install.sh` **一行都不用改**，完全跨平台共用

## 2. 三件事要你拍板

### ① 花不花那 ¥688/年

| | 不花（0 元） | 花（¥688/年） |
|---|---|---|
| 手机会响吗 | ✅ **会**（靠自建 Bark） | ✅ 会（Yxi 自己的通知） |
| 通知上能直接批吗 | ❌ 要点开 App | ✅ 能 |
| 通知上是谁的图标 | ⚠️ **Bark 的** | ✅ Yxi 自己的 |
| 推送私钥 | ⚠️ 全世界共用一把，被轮换就一起哑 | ✅ 自己的，无单点 |
| 灵动岛倒计时 | ❌ | ✅ |
| App 多久失效一次 | **7 天**，要在手机上点刷新 | **1 年** |
| 还有什么风险 | ⚠️ SideStore 的 anisette 服务在国内能不能连，未验证 | — |
| 都要 Mac 吗 | ✅ 要借一次 | ✅ 要，但**一年只用一次** |

**推荐：花。** 主要不是为了推送，是为了**「1 年」而不是「7 天」**——
出门在外发现 App 过期打不开，是这个工具最不该出现的失败模式。

### ② 私钥算法：P-256 还是 ed25519

**推荐 P-256（存 Secure Enclave）**，比 Android 版还安全。
两把密钥并存没有任何问题，`authorized_keys` 里多一行而已。

### ③ Bark 那一层要不要现在就配

**推荐现在就配。** 它跟 iOS App 完全解耦：

- 服务器上装个 bark-server + 一个 5 行的 tail 脚本
- 手机上从 App Store 装 Bark
- **今天就能让手机响**，不用等 iOS App 写完，也不受签名过期影响

**而且它对安卓版零影响** —— 不碰 `yxi-hook`、不碰 `install.sh`、不碰任何现有文件。

## 3. 一句话回答「iOS 版值不值得做」

**值得。** 「手机主动响」这个核心卖点在 iOS 上**不但能做，还做得更好**（不耗电、不被杀、有灵动岛）。

**真正的代价不在功能上，在分发上**：
Android 是「服务器上放个包，点一下就装」，iOS 是「借台 Mac 编译签名，每年（或每周）折腾一次」。

**这件事没有技术方案能绕过去** —— 它是 Apple 的规则，不是我们的能力问题。
