# 怎么把 Yxi 装到 iPhone 上

> 日期：2026-08-23 · 作者：ios-push
> 一句话结论：**没有「从自己服务器下载直接装」这回事。** iOS 上最接近的是 AltStore 自建源，
> 而**每一条路都要么每 7 天重装一次，要么每年花 ¥688。**
>
> ⚠️ 本文作者没有 Mac、没有 iPhone、没有开发者账号，**一个字都没有实机验证过**。
> 没有出处链接的地方标了「（未验证，推断）」。

---

## 0. 先回答那个最关键的问题

> **Android 版是「从自己服务器下 APK 直接装」（`Update.kt` 走 SFTP 取包 → 拉起系统安装器）。
> iOS 上有没有等价物？**

**没有。一个都没有。**

Android 上那件事之所以成立，靠的是两条 iOS 完全没有的东西：

| Android 有 | iOS 有没有 |
|---|---|
| 「未知来源安装」——用户点一下就能装任意 APK | ❌ **没有**。安装必须由 Apple 签名的信任链背书 |
| `REQUEST_INSTALL_PACKAGES` ——**App 可以拉起安装器装另一个 App** | ❌ **没有**。iOS App 不能安装 App，没有任何对应 API |

最接近的三个替代物（详见 §4），**没有一个能做到「点一下就装好」**：

| 替代物 | 有多接近 | 差在哪 |
|---|---|---|
| **AltStore 自建源** | ⭐ **最接近** | 是 AltStore 在装，不是 Yxi 自己在装；要先装 AltStore/SideStore |
| Ad Hoc + `itms-services://` OTA | 挺接近（Safari 点链接直接装） | 要 $99 + **HTTPS 有效证书**（PRD §2.1 好不容易甩掉的东西又回来了）+ 每台设备 UDID 预注册 |
| TestFlight | 更新体验最好 | 走 Apple 的服务器 + 外部测试要过 Beta App Review + **每个 build 90 天过期** |

## 1. 三种签名身份，选哪个

| | **免费 Apple ID** | **$99/年（中国 ¥688）** | 企业账号 |
|---|---|---|---|
| 证书/描述文件有效期 | **7 天** | **1 年** | — |
| 同时能装几个自签 App | **3 个** | 无上限（AltStore 下 10 个） | — |
| **能用推送吗** | ❌ **不能** | ✅ 能 | — |
| Ad Hoc 设备数 | — | 100 台/年（每台要预注册 UDID） | — |
| TestFlight | ❌ | ✅ | — |
| 拿得到吗 | ✅ | ✅ 个人身份证实名，约 48 小时 | ❌ **个人拿不到**（要企业资质 + D-U-N-S），且滥用会被封 |

**免费账号那条「不能用推送」是致命的。**
Push Notifications capability 在免费账号（Personal Team）下**根本不出现在描述文件里**
（[Apple 文档口径](https://www.developer.apple.com/help/account/identifiers/enable-app-capabilities)、
[The Notifications Book](https://thenotificationsbook.com/2018/09/04/do-i-need-a-paid-apple-developer-program-membership-to-use-push-notifications/)）。

→ 免费账号下，Yxi **自己**收不到任何远程推送。
（但 —— `背景通知.md` §1.A 的 Bark 方案**不受影响**，因为响的是 Bark，不是 Yxi。）

**$99 在中国是 ¥688/年**，个人/个体工商户身份注册，要身份证实名验证，
一般 48 小时内过审，年度自动续费（[参考](https://zhuanlan.zhihu.com/p/682442513)）。

## 2. 自签工具：AltStore vs SideStore vs 直接 Xcode

| | **Xcode 直连** | **AltStore Classic** | **SideStore** |
|---|---|---|---|
| 要 Mac 吗 | ✅ 每次都要 | 装的时候要 | **只在第一次安装时要** |
| 之后重签要电脑吗 | ✅ 要 | ✅ **要**（AltServer 得在同一个 WiFi 上跑着） | ❌ **不用，手机上自己刷** |
| 怎么刷 | 插线重新 Run | AltServer 自动刷 | 机上用 StosVPN 完成签名 |
| 免费账号刷新周期 | 7 天 | 7 天 | 7 天 |
| 付费账号刷新周期 | **1 年** | **1 年** | **1 年** |

（[SideStore FAQ](https://docs.sidestore.io/docs/faq)、
[AltStore vs SideStore 2026](https://builds.io/blog/technologies/ios-technologies/sidestore-vs-altstore/)、
[AltStore Wikipedia](https://en.wikipedia.org/wiki/AltStore)）

**SideStore 是免费方案里唯一能忍的**：装完之后不用再碰电脑，
每 7 天在手机上点一下刷新就行。
⚠️ **未验证**：SideStore 依赖 anisette 服务器做 Apple 认证，**国内网络下是否稳定不知道**。
这是免费路线最大的实际风险 —— 如果 anisette 连不上，就刷不了，App 到期就打不开。

**TrollStore —— 已死，别考虑。**
它靠的 CoreTrust 漏洞在 **iOS 17.0.1 被永久修复**，17.0.1 以上（含 iOS 18、iOS 26）无解，
作者明确说除非发现第三个 CoreTrust bug 否则不会再支持
（[TrollStore README](https://github.com/opa334/TrollStore)、[The Apple Wiki](https://theapplewiki.com/wiki/TrollStore)）。
只有手上是停留在 ≤16.6.1 / 17.0 的老机器才用得上。

## 3. 欧盟替代应用商店 —— **确认不适用**

任务书让确认这条，结论是：**用户在中国，完全用不了。**

Apple 的条件是**两条同时满足**（[Apple 官方支持页](https://support.apple.com/en-us/117767)）：

1. Apple 账号的国家/地区必须是**欧盟成员国**之一（27 国名单）
2. **人必须实际在欧盟境内**

而且：

- 地理校验**在设备本地做**，**VPN 绕不过去**
- 一旦离开欧盟，**已经装的 App 无法再更新**，也不能装新的应用商店
  （[9to5Mac](https://9to5mac.com/2024/03/05/ios-17-4-app-stores-stop-working-travel/)）

→ AltStore PAL 这类欧盟替代商店，**对本项目一行价值都没有**。写在这里是为了以后别再问一遍。

## 4. 三条实际可走的分发路，逐条算账

### 4.A 免费账号 + SideStore —— 0 元，代价是每 7 天点一次

```
Mac（一次）→ 编译 .ipa → SideStore 装上 → 之后每 7 天在手机上点「刷新」
```

- **成本：0 元**（但仍然需要**借一台 Mac 用一次**）
- 每 7 天必须刷一次，**过期了 App 直接打不开**
- 同时最多 3 个自签 App
- **Yxi 收不到推送**（§1）→ 必须配 `背景通知.md` §1.A 的 Bark 方案，靠 Bark 来响
- ⚠️ anisette 国内可用性未验证

**这条路的真实体感：** 「手机会响」这件事是 Bark 在保证的，稳；
但「点开通知之后能不能进 Yxi」取决于你这周刷没刷。**出门在外发现 App 过期了是最糟的场景。**

### 4.B $99/年 + AltStore/SideStore —— **推荐**

```
Mac（每年一次）→ 编译签名 → AltStore 装上 → 一年刷一次
```

- **成本：¥688/年 + 一台 Mac（每年用一次）**
- 证书 1 年有效 → **一年折腾一次**
- **能用推送** → Yxi 自己的通知、通知上直接批、灵动岛倒计时（`背景通知.md` §1.B / §1.F）
- 不需要 UDID 注册、不需要 HTTPS 服务器、不需要过任何审核

**这是唯一一条「装上之后基本不用管」的路。**

### 4.C $99/年 + Ad Hoc OTA —— 最像「从自己服务器装」，但代价最重

自己服务器上放 `manifest.plist` + `.ipa`，Safari 点一个 `itms-services://` 链接直接装
（[流程](https://softmoco.com/en/devenv/how-to-host-ipa-file-for-ad-hoc-distribution.php)）。

四条硬要求：

1. **必须 HTTPS + 有效 CA 证书**，iOS 拒绝 HTTP
   → ⚠️ **PRD §2.1 好不容易甩掉的「Let's Encrypt / 域名 / 挂公网」全部回来了**
2. **每台设备的 UDID 必须先在开发者后台注册**，100 台/年（对自用够，但要先拿到 UDID）
3. 要 $99 账号
4. 证书到期（1 年）App 照样打不开

**结论：对自用不划算。** 它是给「发给一小撮同事测试」用的，
我们只有一台手机，用 4.B 更省。**除非**以后要给别的用户分发，那时再回头看这条。

### 4.D TestFlight —— 不推荐，但要知道它存在

- 要 $99；外部测试组的第一个 build 要过 **Beta App Review**（1~2 天）
- **每个 build 90 天过期**，到期要重新上传
- 内部测试 100 人 / 外部测试 10000 人
  （[参考](https://techconcepts.org/blog/testflight-guide)）

**跟项目主张冲突最大的一条**：包要上传到 Apple 的服务器、要过 Apple 的审核。
对「一个人自己用的遥控器」来说是纯负担。

## 5. 自更新怎么办 —— **`Update.kt` 那条路完全走不通**

安卓版的自更新（`android/.../agent/Update.kt` + `ui/UpdateCard.kt`）是：

```
SFTP 读 ~/.yxi/latest.json → 比 versionCode → SFTP 下载 Yxi.apk
  → FileProvider → 拉起系统安装器
```

**后半截在 iOS 上一步都做不了**：没有 `REQUEST_INSTALL_PACKAGES`、
没有 FileProvider 交给安装器这回事、**App 不能安装 App**。

### 能保留的部分

**前半截原样可用，而且应该保留。** `Update.kt` 里那套设计（走 SFTP 不走 HTTP、
「有新版本 / 已是最新 / 连不上没查到」三种结果必须分清 —— 决策 D23）是对的，
跟平台无关，iOS 侧照搬：

```
SFTP 读 ~/.yxi/latest.json → 比版本号 → 显示「服务器上有 0.3.0」
                                        → 然后 ⚠️ 只能给一个可点的链接
```

### 「可点的链接」指向哪 —— 三个选择

| 方案 | 链接长什么样 | 前置条件 | 体验 |
|---|---|---|---|
| ⭐ **AltStore 自建源** | `altstore://source?url=https://你的服务器/apps.json` | 装了 AltStore/SideStore | AltStore 检测到版本号变高会**主动提示更新**，点一下装 |
| Ad Hoc OTA | `itms-services://?action=download-manifest&url=https://…/manifest.plist` | $99 + HTTPS 有效证书 + UDID 已注册 | Safari 里点一下直接装，**最接近安卓版体验** |
| 什么都不做 | 显示一句「服务器上有新版，去 Mac 上重新编译装一下」 | — | 诚实但难受 |

### 推荐：AltStore 自建源

AltStore 的「源」就是**你自己服务器上的一个 JSON 文件**，列出 App 名字、版本号、IPA 直链、
更新说明；**AltStore 会在版本号变高时主动提示用户更新**
（[Make a Source](https://faq.altstore.io/developers/make-a-source)、
[AltStore Sources 文档](https://github.com/altstoreio/AltStore-Docs/blob/master/sources.md)）。

这跟服务器上现有的 `~/.yxi/latest.json` **是同一类东西、同一个成本**：

```
~/.yxi/latest.json   ← 安卓版现在就在用（install.sh --publish 写的）
~/.yxi/Yxi.apk
~/.yxi/apps.json     ← 新增：AltStore 源（同样一条 --publish 顺手写）
~/.yxi/Yxi.ipa
```

⚠️ **但有一个坑**：AltStore 源里的 IPA 直链得是 **HTTP(S) 可达**的，
而 `~/.yxi/` 现在是**只能走 SFTP** 的（PRD 特意选 SFTP 就是为了不开 HTTP 面）。
→ 要么在服务器上开一个只读的静态 HTTP 服务（跟 PRD §2.3「不开任何新端口」冲突），
要么 IPA 放别处（比如 GitHub Release —— 私有仓要 token，也是个坑）。
**这个矛盾没有干净的解，是 iOS 侧要付的税之一。**
// ⚠️ 未验证：AltStore 源是否支持非 HTTPS 的直链、是否能走已有的 SSH 端口转发。

⚠️ **另一个坑**：AltStore 源里的 IPA **是未签名的**，AltStore 用**你自己的账号**在装的时候重签。
所以「自建源」不解决证书有效期问题 —— 免费账号装完还是 7 天。

## 6. 硬门槛：Mac

**没有 Mac 就编译不出 `.ipa`。** Xcode 只有 macOS 版，签名工具链也只在 macOS 上。
这是所有路线共同的前置条件，**没有绕过去的办法**。

三个选项：

| | 成本 | 说明 |
|---|---|---|
| 借/买一台 Mac | Mac mini 起步 | 最省心。付费账号下**一年只用一次** |
| 云 Mac（MacStadium 等） | 按月 | 要把签名私钥传上去，自己权衡 |
| GitHub Actions 的 macOS runner | 公开仓免费 | 能编译能签名，但要把 `.p12` 证书 + 描述文件放进 Secrets。<br>// ⚠️ 未验证：**免费 Apple ID 的签名在 CI 上多半走不通**（要交互式 Apple ID 登录），付费账号导出的证书可以 |

## 7. 用户实际要付出什么 —— 可执行清单

### 想要「手机会响 + 装上之后基本不用管」（推荐）

1. **注册 Apple Developer Program，¥688/年**（个人身份证实名，约 48 小时）
2. **搞一台 Mac**（借、买、或云 Mac —— 付费账号下**一年只用一次**）
3. 在 Mac 上编译 + 签名，用 AltStore/SideStore 装到手机
4. 服务器上放 `.p8` + Key ID + Team ID，加一个推送脚本（`背景通知.md` §1.B）
5. **每年重签一次**

**年成本：¥688 + 一次 Mac 的使用 + 一年一次的重签。**

### 不想花钱（最小可用）

1. **服务器上装 bark-server，手机上装 App Store 的 Bark** → 「手机会响」这件事**立刻就有了，0 元**
2. Yxi App 用免费 Apple ID 自签，**SideStore 装上，每 7 天在手机上点一次刷新**
3. Yxi 本身**收不到推送** → 靠 Bark 响，点开 Bark 通知再手动开 Yxi
4. 仍然要**借一台 Mac 编译一次**

**年成本：0 元 + 每 7 天点一次 + anisette 能不能连的风险。**

> 💡 **注意这两条路的第 1 步是可以先做的**：
> Bark 那一层跟 Yxi App 完全解耦，**今天就能配好**，
> 不用等 iOS App 写完、也不受签名过期影响。
> 建议先把它跑起来 —— 「Claude 找你」这件事从此就不丢了。

## 8. 这一份对决策 D7 的意见

> **D7：「只做 Android，iOS 第一期不做 —— 苹果不允许从 GitHub Release 安装，与 D6 本质冲突。」**

**D7 的事实判断是对的，结论需要更新。**

- ✅ **事实部分完全成立**：iOS 确实装不了 GitHub Release 上的包，
  「只发 Release」和「支持 iOS」确实本质冲突（§0 已再次确认，且 TrollStore 死后更彻底了）
- ⚠️ **但 D7 漏了一件事**：PRD §2.5 把 iOS 的三条路都算成「代价」，
  却没发现**「手机主动响」这件事在 iOS 上可以完全脱离分发问题独立解决**（Bark，§7）。
  也就是说 —— **就算 iOS App 一行都不写，用户今天也能让手机响。**
- ⚠️ **PRD §2.5 那句「TestFlight 外部测试上限 100 人」写错了**：
  实际是**外部 10000 人 / 内部 100 人**（[参考](https://techconcepts.org/blog/testflight-guide)）。
  不影响结论（TestFlight 仍然不推荐），但数字该改。

**建议 D7 改写成**：

> iOS 版**放弃「从服务器下载直接装」这个形态**（iOS 上不存在等价物）。
> 分发改为 **AltStore/SideStore 自签**，自更新改为 **AltStore 自建源**。
> 「手机主动响」**不依赖 App 分发**，用自建 bark-server 独立解决，零成本。
> 想要「通知上直接批 + 灵动岛倒计时 + 一年只折腾一次」→ ¥688/年。
